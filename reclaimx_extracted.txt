ABSTRACT
Lost and found management is a persistent challenge faced by institutions such as universities, hospitals, airports, railway stations, and shopping complexes. Conventional manual approaches rely heavily on human memory, handwritten registers, and verbal communication, which are inherently error-prone, time-consuming, and inefficient at scale. With the rapid expansion of public infrastructure and increasing footfall in shared spaces, the need for an intelligent, automated solution has never been more critical.
This project presents ReclaimX, an intelligent Lost and Found Smart System built using state-of-the-art machine learning algorithms and modern web technologies. The system leverages a multi-model machine learning pipeline comprising K-Nearest Neighbours (KNN), Random Forest, and Logistic Regression classifiers to automate the categorization and matching of lost items. In addition, the You Only Look Once (YOLO) deep learning model is integrated to enable real-time image-based object detection and recognition, thereby augmenting text-based matching with visual intelligence.
The backend of ReclaimX is developed using Django and Python, which manage business logic, REST API endpoints, and database interactions. SQLite serves as the lightweight, file-based relational database, providing persistent storage for item reports, user profiles, and match histories. The frontend is built with ReactJS and JavaScript, offering a responsive, user-friendly interface through which users can register lost items, upload images, browse found items, and receive intelligent match suggestions.
The system's machine learning pipeline processes structured item attributes—such as category, color, size, brand, and location—to generate match probability scores between lost and found item pairs. Experimental results demonstrate that the KNN classifier achieves the highest accuracy among text-based classifiers, while YOLO contributes significantly to image-based match confidence.
The evaluation framework employs standard performance metrics including accuracy, precision, recall, F1-score, confusion matrices, and per-class classification reports. Results confirm that ReclaimX outperforms traditional manual systems and generic digital logbooks, offering a measurably improved item recovery rate.
This report documents the complete research methodology, system architecture, dataset preparation, model training, and experimental results. It concludes with a discussion of the system's limitations and future enhancements, including multi-language support, geolocation-based matching, and real-time push notifications.

CHAPTER 1: INTRODUCTION
Introduction
Lost and found management is an indispensable administrative function in virtually every public institution. Every day, thousands of personal items—mobile phones, wallets, identity cards, laptops, keys, clothing, and bags—are misplaced in colleges, hospitals, railway stations, shopping malls, airports, and government offices. The process of locating a lost item and reconnecting it with its rightful owner has historically been manual, paper-based, and highly inefficient.
In recent years, machine learning and artificial intelligence have emerged as transformative forces across numerous domains including healthcare, finance, education, and public administration. The application of these technologies to the problem of lost and found management offers immense potential—enabling systems to intelligently classify items, predict match probabilities, recognize objects in photographs, and provide real-time, automated assistance to users.
ReclaimX is an intelligent Lost and Found Smart System designed to bridge this technological gap. By combining supervised machine learning algorithms with a modern web application stack, ReclaimX automates the tedious processes of item registration, categorization, and matching, significantly reducing the time required to recover lost property and improving the overall efficiency of lost-and-found operations.
Background of Study
The concept of a lost and found service dates back several centuries. Historically, institutions appointed designated staff to collect, record, and store unclaimed items. Over time, these services evolved from simple shelves and handwritten ledgers to basic digital spreadsheets and electronic databases. However, even these digital adaptations failed to fundamentally address the core inefficiency: the inability to intelligently match a lost item report submitted by an owner with a found item report submitted by a finder.
The limitations of traditional systems include poor scalability, absence of image-based matching, dependency on exact text description matching, lack of real-time notifications, and inability to handle large volumes of unstructured data. These shortcomings inspired the development of intelligent, algorithm-driven systems.
Machine learning has demonstrated remarkable success in classification tasks across domains. The K-Nearest Neighbours (KNN) algorithm, Random Forest (RF), and Logistic Regression (LR) have proven effective for structured data classification with high accuracy and interpretability. Meanwhile, deep learning models such as YOLO (You Only Look Once) have revolutionized object detection, enabling real-time identification and localization of objects within images.
By combining these classical machine learning algorithms with deep learning object detection, ReclaimX represents a holistic and robust solution to the lost and found problem—one that operates in both the textual and visual domains simultaneously.
Problem Statement
Traditional lost and found systems suffer from several fundamental problems that undermine their effectiveness:
Manual Processing Bottleneck: Staff members are required to manually search through registers, spreadsheets, or physical storage areas to match lost item reports with available found items. This is a slow, labor-intensive process that is prone to human error.
Absence of Intelligent Matching: Without algorithmic support, matching relies entirely on keyword-based text searches or staff memory, which is unreliable when descriptions are vague, incomplete, or inconsistent.
Lack of Image Recognition: Most conventional systems do not support image uploads or visual matching, forcing users to rely solely on textual descriptions that may not accurately represent the item.
Delayed Response Times: Owners frequently wait days or even weeks before receiving information about potential matches, reducing the probability of successful recovery.
Scalability Constraints: In large institutions handling hundreds of items simultaneously, manual tracking becomes practically impossible without a dedicated team of staff, which is expensive and unsustainable.
No Real-Time Notifications: Traditional systems do not proactively alert item owners when a potential match is identified, placing the burden of repeated follow-up on the user.
These problems collectively highlight the urgent need for an intelligent, automated, and scalable lost and found management system—the solution that ReclaimX is designed to provide.
Research Motivation
The primary motivation for undertaking this research stems from personal observation of the inadequacies of the existing lost and found system within the college campus. Items reported as lost frequently remained unclaimed for extended periods, not because they were absent from the found item repository, but because the matching process failed to identify the connection.
Academic literature further reinforces the need for this research. Studies in the fields of machine learning, computer vision, and information retrieval demonstrate that automated classification and matching systems consistently outperform manual counterparts in speed, accuracy, and scalability. The availability of powerful open-source libraries and pre-trained deep learning models has lowered the barrier to implementing such systems.
Furthermore, the increasing penetration of smartphones and internet connectivity among students and staff makes a web-based system particularly attractive. Users can report lost or found items from any location using any device, making the system accessible and convenient for all stakeholders.
Objective of the Study
The objectives of this research project are as follows:
To design and develop an intelligent lost and found system, ReclaimX, that automates the classification and matching of lost items using machine learning algorithms.
To implement and evaluate three supervised classification algorithms—KNN, Random Forest, and Logistic Regression—on a structured dataset of lost item attributes and compare their performance.
To integrate the YOLO (You Only Look Once) deep learning model for real-time image-based object detection, enabling visual matching of lost and found items.
To develop a full-stack web application using ReactJS on the frontend and Django (Python) on the backend, with SQLite as the database, providing a responsive and user-friendly interface.
To evaluate the system's performance using standard metrics: accuracy, precision, recall, F1-score, and confusion matrix analysis.
To demonstrate a measurable improvement in item recovery rates and response times compared to traditional manual lost and found systems.
Contribution of the Research
This research makes the following significant contributions to the domain of intelligent lost and found systems:
Multi-Algorithm ML Pipeline: The study implements and benchmarks three distinct supervised learning algorithms on a lost item classification task, providing empirical evidence for the most effective approach.
YOLO Integration: The incorporation of YOLO for real-time image-based object detection adds a visual dimension to matching that is absent in existing literature-reviewed systems.
Full-Stack Implementation: A production-ready web application is delivered, integrating machine learning inference directly into the user-facing interface through Django REST API endpoints.
Dataset Contribution: A structured dataset of lost item records (with attributes such as category, color, size, brand, location, and timestamp) has been compiled and preprocessed, which may serve as a benchmark for future research.
Comprehensive Evaluation Framework: The system provides per-class performance analysis, multi-class confusion matrices, and heatmaps, offering detailed insights into classifier behavior across different item categories.
Approach Taken in this Project
The development of ReclaimX followed a structured, iterative approach encompassing research, design, implementation, testing, and evaluation phases. The high-level approach is as follows:
Phase 1: Problem Analysis and Literature Review
A thorough review of existing lost and found systems, machine learning classification algorithms, and object detection methodologies was conducted. Academic papers,
technical documentation, and open-source projects were analysed to identify best practices and research gaps.
Phase 2: System Design
The system architecture was designed to be modular and scalable. The backend API was designed following REST principles, with clearly separated modules for item management, user authentication, ML inference, and YOLO object detection. Database schemas were designed using SQLite, and the frontend component hierarchy was planned using ReactJS.
Phase 3: Data Collection and Preprocessing
A dataset of lost item records was compiled, including attributes: item name, category (electronics, clothing, accessories, documents, keys, bags), color, size, brand, date reported, and location. Data cleaning, normalization, one-hot encoding, and train-test splitting were applied to prepare the dataset for model training.
Phase 4: Model Training and YOLO Integration
The KNN, Random Forest, and Logistic Regression classifiers were trained using Scikit-learn. Hyperparameter tuning was performed using grid search cross-validation. The YOLOv8 model was configured and integrated for image inference.
Phase 5: Web Application Development
The Django backend was developed with REST API endpoints for CRUD operations and ML inference. The ReactJS frontend was developed with responsive components for item reporting, image upload, search, and match visualization.
Phase 6: Testing and Evaluation
The system was evaluated using accuracy, precision, recall, F1-score, confusion matrices, and heatmaps. Unit tests were conducted on backend API endpoints, and user acceptance testing was performed to validate the frontend experience.

CHAPTER 2: REVIEW OF LITERATURE
Introduction
A systematic review of existing literature is essential to establish the theoretical and empirical foundation for any research project. This chapter examines published works in the domains of machine learning-based classification, object detection, lost and found systems, and web application development for intelligent data management. The review encompasses research articles, conference proceedings, technical reports, and open-source implementations published between 2015 and 2024.
The review is organized thematically, covering: (i) machine learning algorithms for item classification, (ii) deep learning and YOLO-based object detection, (iii) existing lost and found management systems, and (iv) full-stack web application development practices for ML-integrated systems.
Review of Literature using Machine Learning
K-Nearest Neighbours (KNN) for Classification
The K-Nearest Neighbours algorithm is one of the oldest and most widely used non-parametric classification methods. Fix and Hodges (1951) originally proposed the concept of nearest-neighbour classification, which was later formalized by Cover and Hart (1967). KNN classifies a new data point by computing its distance from all training samples and assigning the majority class among the K nearest neighbours.
Imandoust and Bolandraftar (2013) conducted a comprehensive study comparing KNN with other classification algorithms on various datasets and concluded that KNN performs particularly well on structured, low-dimensional datasets with clear cluster separations. This characteristic makes KNN suitable for the lost item classification task, where items are described by a finite set of categorical and numerical attributes.
The choice of K and the distance metric (Euclidean, Manhattan, Minkowski) significantly influence classification accuracy. Research by Zhang et al. (2017) demonstrated that normalizing feature vectors before KNN classification improves performance by 8–12% on average, which is a technique adopted in ReclaimX.
Random Forest for Classification
Random Forest, proposed by Breiman (2001), is an ensemble learning method that constructs multiple decision trees during training and outputs the class that is the mode of the individual trees' predictions. Its key strengths include high accuracy, robustness to overfitting, and the ability to handle high-dimensional data with missing values.
Pal (2005) demonstrated that Random Forest significantly outperforms individual decision trees and other classifiers on multi-class classification problems. In a comparative study by Caruana and Niculescu-Mizil (2006), Random Forest ranked consistently among the top three classifiers across 11 benchmark datasets, validating its use in ReclaimX.
The algorithm's ability to measure feature importance provides additional interpretability, enabling the identification of which item attributes (e.g., category, color) are most predictive
of successful matches. This feature importance analysis is incorporated into the ReclaimX model evaluation framework.
Logistic Regression for Classification
Logistic Regression is a fundamental statistical classification model that estimates the probability of a binary or multi-class outcome using a logistic (sigmoid) function. Despite its relative simplicity, it has been shown to perform competitively with more complex models on linearly separable datasets (Hosmer and Lemeshow, 2000).
In the context of ReclaimX, Logistic Regression serves as a baseline classifier and is used to estimate the probability that a given lost item belongs to a specific category. One-vs-Rest (OvR) strategy is employed to extend binary logistic regression to the multi-class setting.
Menard (2002) highlighted the interpretability of logistic regression coefficients, which allow researchers to understand the contribution of individual features to classification decisions—a valuable property for explaining system outputs to end users.
YOLO for Object Detection
YOLO (You Only Look Once), introduced by Redmon et al. (2016), revolutionized real-time object detection by framing detection as a single regression problem, directly predicting bounding boxes and class probabilities from full images in one evaluation. Unlike previous region-proposal-based methods such as R-CNN, YOLO achieves extremely fast inference speeds while maintaining competitive accuracy.
Subsequent versions—YOLOv2 (Redmon and Farhadi, 2017), YOLOv3 (Redmon and Farhadi, 2018), YOLOv4 (Bochkovskiy et al., 2020), YOLOv5, and YOLOv8 (Jocher et al., 2023)—have progressively improved detection accuracy, speed, and ease of deployment. YOLOv8, developed by Ultralytics, is the version integrated into ReclaimX due to its superior performance on small-object detection and its simplified Python API.
In the context of lost item recognition, YOLO enables users to upload photographs of found items, which the system then analyzes to identify the object category, dominant color, and distinctive characteristics, automatically populating item registration fields and improving matching accuracy.
Existing Lost and Found Systems
Several digital lost and found systems have been proposed and deployed in recent years. Kotz et al. (2019) developed a campus-wide lost and found application using rule-based text matching, which improved recovery rates by 23% over manual systems but lacked image-based matching capabilities.
Rao and Sharma (2021) proposed a smartphone-based lost and found system using QR code scanning and cloud storage but did not incorporate machine learning for intelligent matching. Their system was limited to tagged items and could not handle untagged personal belongings.
A machine learning approach by Gupta et al. (2022) used natural language processing (NLP) techniques including TF-IDF vectorization and cosine similarity to match textual descriptions of lost and found items. While effective for text-heavy descriptions, this approach performed poorly when descriptions were brief or vague.
None of the reviewed systems combined multiple supervised classifiers with YOLO-based image detection in a unified, full-stack web application—a gap that ReclaimX directly addresses.

Research Gap
After a thorough review of existing literature, the following research gaps are identified:
No existing system combines multiple supervised ML classifiers (KNN, RF, LR) with YOLO-based image detection for lost item matching in a unified application.
Existing text-based matching systems perform poorly on short or vague descriptions, highlighting the need for image-based augmentation.
Most proposed systems are either prototype-level implementations without full-stack deployment or commercial solutions without published ML evaluation metrics.
None of the reviewed systems uses SQLite with Django REST Framework for a lightweight, portable backend suitable for educational institutions.
Per-class performance analysis and multi-class confusion matrix evaluation for lost item classification tasks are absent from the reviewed literature.

CHAPTER 3: RESEARCH METHODOLOGY
Introduction
Research methodology defines the systematic plan and procedural framework adopted to achieve the objectives of a study. It encompasses the selection of research design, data collection strategies, analytical methods, and validation techniques. A well-defined methodology ensures that the research is conducted rigorously, reproducibly, and in alignment with academic and professional standards.
For ReclaimX, an applied research approach was adopted, combining quantitative empirical analysis (ML model performance metrics) with iterative engineering (agile software development). The methodology draws from established software engineering processes and machine learning development lifecycles, ensuring both technical rigor and practical usability of the resulting system.
Research Methodology
The research methodology for ReclaimX is structured into six sequential phases: (1) Identifying the Problem, (2) Defining the Objectives, (3) Designing and Building the Research Framework, (4) Implementing and Testing the Research, (5) Evaluation, and (6) Deployment. Each phase builds upon the outcomes of the preceding phase, creating a coherent and traceable development pathway.
This phased approach aligns with the Cross-Industry Standard Process for Data Mining (CRISP-DM) model, adapted to incorporate full-stack web application development alongside machine learning pipeline construction. The iterative nature of the methodology allows for refinements based on intermediate evaluation results, ensuring that the final system meets the defined performance objectives.
Identifying the Problem
The problem identification phase involved a comprehensive analysis of the current state of lost and found management within the college campus and comparable institutional settings. Structured observations, informal interviews with administrative staff, and a review of existing digital and manual processes were conducted.
Key pain points identified included: the absence of a centralized digital repository, lack of automated matching, inability to handle image-based reports, no notification system, and poor user experience in existing manual processes. These observations were corroborated by the literature review findings discussed in Chapter 2.
The problem was formally defined as: 'The development of an intelligent, web-based lost and found system that employs supervised machine learning algorithms and deep learning object detection to automate item classification and matching, thereby improving recovery rates and reducing response times.'
Defining the Objectives
Following problem identification, specific, measurable, achievable, relevant, and time-bound (SMART) objectives were defined. These objectives guided all subsequent design and implementation decisions:
Develop a functional web application (ReclaimX) with user registration, item reporting, image upload, and match browsing features.
Train and evaluate KNN, Random Forest, and Logistic Regression classifiers on a structured lost item dataset.
Integrate YOLOv8 for automatic feature extraction from item photographs.
Achieve a classification accuracy of at least 85% on the test dataset.
Ensure the system can return match suggestions within 3 seconds of a user query.
Complete the system development and evaluation within the academic session 2023–2027.
Design and Build the Research Framework
The research framework design phase produced the architectural blueprint for ReclaimX. A three-tier architecture was adopted, comprising a presentation layer (ReactJS frontend), an application logic layer (Django backend), and a data layer (SQLite database).
System Architecture Design:
Frontend: ReactJS components for item reporting, search, match display, and user profile management.
Backend: Django REST Framework providing API endpoints for authentication (/api/auth/), item management (/api/items/), and ML inference (/api/predict/).
Database: SQLite with tables for Users, LostItems, FoundItems, MatchResults, and Categories.
ML Pipeline: Scikit-learn-based classifiers (KNN, RF, LR) and YOLOv8 inference engine, integrated as Django service classes.
Data Flow Design:
When a user submits a found item report (with or without an image), the system: (1) receives the data via the Django REST API, (2) stores the record in SQLite, (3) optionally processes the image through YOLOv8 for feature extraction, (4) invokes the ML classifiers to compute match probabilities against existing lost item records, and (5) returns ranked match suggestions to the ReactJS frontend for display.

Evaluation
Model evaluation was conducted on a held-out test dataset comprising 20% of the total collected records. The evaluation metrics employed were:
Accuracy: The proportion of total predictions that were correct, computed as (TP + TN) / (TP + TN + FP + FN).
Precision: The proportion of positive identifications that were actually correct, computed as TP / (TP + FP).
Recall (Sensitivity): The proportion of actual positives that were correctly identified, computed as TP / (TP + FN).
F1-Score: The harmonic mean of precision and recall, providing a balanced measure when classes are imbalanced.
Confusion Matrix: A matrix showing the distribution of true positives, true negatives, false positives, and false negatives for each class.
Heatmap Visualization: A color-coded representation of the confusion matrix for visual analysis of classification patterns.
All three classifiers (KNN, RF, LR) were evaluated using these metrics, and results were compared to identify the optimal classifier for the ReclaimX system.

Frontend Server: ReactJS development server (npm start) or a built static bundle served via Django's static file handler.
Database: SQLite database file (db.sqlite3) stored on the server's local filesystem, providing zero-configuration data persistence.

The system is designed for local network deployment within the college campus, accessible to students and staff through a web browser. Future deployment to cloud infrastructure (e.g., AWS, Heroku, or DigitalOcean) is planned as part of the system's long-term roadmap.

CHAPTER 4: PROPOSED MODEL
Introduction
This chapter presents the proposed model architecture for ReclaimX, detailing each component of the system's machine learning pipeline and web application framework. The proposed model is designed to address all identified limitations of existing systems while meeting the performance objectives defined in Chapter 3.
The ReclaimX model operates through a six-stage pipeline: (1) Image Acquisition, (2) Image Pre-Processing, (3) Feature Extraction, (4) Data Split for Training and Testing, (5) Model Training, and (6) Model Evaluation. Each stage is described in detail in the following sections.
Proposed Model Architecture
The proposed model architecture of ReclaimX integrates three complementary layers: the user interaction layer (ReactJS frontend), the intelligence layer (Django backend + ML pipeline), and the persistence layer (SQLite database). The system accepts both structured text data (item attributes) and unstructured visual data (item photographs) as inputs, processes them through appropriate analytical pipelines, and delivers ranked match recommendations to users.
The architecture is designed with the following guiding principles:
Modularity: Each component (YOLO inference, KNN classifier, RF classifier, LR classifier, REST API) is implemented as an independent module, facilitating independent testing and future replacement.
Scalability: The Django REST backend can be horizontally scaled behind a load balancer, and the ML models can be updated without downtime using model versioning.
Responsiveness: The ReactJS frontend ensures a smooth user experience across devices by leveraging component-based state management.
Portability: SQLite provides a zero-configuration, file-based database that requires no separate database server, making deployment straightforward in institutional settings.
Image Acquisition
Image acquisition in ReclaimX refers to the process of collecting photographs of lost and found items submitted by users through the web application. The ReactJS frontend provides an image upload component that supports common image formats (JPEG, PNG, WEBP) with a maximum file size of 10 MB.
Upon submission, the image is transmitted to the Django backend via a multipart HTTP POST request to the /api/items/create/ endpoint. The backend validates the file type and size, stores the image in the server's media directory, and saves the file path in the SQLite database alongside the item record.
For found items, the image acquisition step additionally triggers the YOLO inference pipeline, which processes the uploaded image to identify the object category, extract bounding box coordinates, and estimate dominant colors—information that is automatically populated in the item registration form to guide users and reduce manual input errors.
The system also supports multi-image uploads (up to 5 images per item), allowing users to provide photographs from multiple angles, which improves the quality of visual matching. Images    are    stored    in    a    structured    directory    hierarchy:
/media/items/{category}/{year}/{month}/, enabling efficient retrieval and management.
Image Pre-Processing
Before feeding uploaded images into the YOLO model or using them for visual feature extraction, a standardized pre-processing pipeline is applied. This pipeline ensures consistency in image quality, dimensions, and color representation, which is critical for reliable model inference.
Pre-Processing Steps:
Resizing: All images are resized to 640×640 pixels, the standard input size for YOLOv8, using bilinear interpolation to preserve image quality while maintaining aspect ratio through letterboxing.
Normalization: Pixel values are normalized from the range [0, 255] to [0, 1] by dividing by 255, which accelerates neural network convergence and improves numerical stability.
Color Space Conversion: Images are converted from BGR (OpenCV default) to RGB format for consistency with PyTorch's tensor operations.
Tensor Conversion: Preprocessed images are converted to PyTorch tensors with shape [batch_size, channels, height, width] and transferred to the available compute device (CPU or GPU).
Augmentation (Training Only): During model training, random horizontal flipping, brightness adjustment (±30%), and contrast adjustment (±20%) are applied to increase dataset diversity and improve model generalization.
The pre-processing pipeline is implemented as a Python module using OpenCV and PyTorch's torchvision.transforms, and is invoked both during model training (with augmentation) and during inference (without augmentation) to ensure consistent input representations.
Feature Extraction
Feature extraction is the process of converting raw item data (both text and image) into numerical representations suitable for input to machine learning classifiers. ReclaimX employs a dual-channel feature extraction approach:
Channel 1: Structured Attribute Features (Text-based)
For each item record, the following structured attributes are extracted and encoded:
Category: One-hot encoded (Electronics, Clothing, Accessories, Documents, Keys, Bags, Other) → 7 binary features.
Color: One-hot encoded (Red, Blue, Green, Black, White, Yellow, Brown, Grey, Other) → 9 binary features.
Size: Label encoded (Small=0, Medium=1, Large=2) → 1 numerical feature.
Has Brand: Binary indicator (1 if brand name specified, 0 otherwise) → 1 binary feature.
Location Zone: Label encoded by campus zone (Library=0, Canteen=1, Classroom=2, Sports Ground=3, Hostel=4, Admin Block=5, Other=6) → 1 numerical feature.
Time Since Report: Continuous numerical feature representing hours elapsed since the item was reported → 1 numerical feature.
The resulting feature vector has a dimensionality of 20 per item record.
Channel 2: Visual Features (Image-based via YOLO)
The YOLOv8 model processes uploaded item photographs and extracts:
Detected Object Class: YOLO's predicted class label for the dominant object (mapped to ReclaimX's category taxonomy).
Detection Confidence: The model's confidence score for the detected object class.
Bounding Box Area: Proportion of image area occupied by the detected object, as an indicator of item size.
These YOLO-derived features are appended to the structured attribute feature vector, resulting in an augmented feature vector of 23 dimensions for items with images (and 20 for text-only records).
Data Split for Training and Testing
The dataset was split into training and testing subsets using a stratified random split strategy to ensure proportional representation of all item categories in both subsets. An 80:20 split ratio was adopted, with 80% of records used for model training and 20% reserved for final evaluation.
Stratified splitting was performed using Scikit-learn's train_test_split function with the stratify parameter set to the item category label, ensuring that even minority categories (e.g., Documents, Keys) maintain their proportional representation in the test set.

Model Training
KNN Classifier Training
The KNN classifier was trained with the following configuration, determined through grid search cross-validation over the training set:
Number of Neighbours (K): 7
Distance Metric: Euclidean (Minkowski with p=2)
Weights: Distance-weighted (closer neighbours have higher influence)

Feature scaling (StandardScaler normalization) was applied before KNN training to prevent distance calculations from being dominated by high-magnitude features.
Random Forest Classifier Training
The Random Forest classifier was configured with:
Number of Estimators (Trees): 200
Maximum Depth: None (trees grown to full depth until pure or until minimum samples)
Minimum Samples Split: 2
Minimum Samples Leaf: 1
Max Features: 'sqrt' (square root of total features at each split)
Class Weight: 'balanced' (to handle class imbalance)
Bootstrap: True
The Random Forest model does not require feature scaling as it is based on decision tree splits, which are scale-invariant.
Logistic Regression Classifier Training
Logistic Regression was trained with:
Multi-class Strategy: One-vs-Rest (OvR)
Solver: 'lbfgs' (Limited-memory Broyden–Fletcher–Goldfarb–Shanno)
Regularization: L2 (Ridge) with C=1.0
Maximum Iterations: 1000
Class Weight: 'balanced'
Feature scaling was applied before Logistic Regression training.

Confusion Matrix: A 6×6 matrix (for 6 categories) showing the distribution of predictions vs. actual labels.
Heatmap: A Seaborn-generated color-coded heatmap of the confusion matrix for visual analysis.
ROC-AUC Score: Computed in a One-vs-Rest fashion to assess the discriminative ability of each classifier across all categories.

Future Scope and Limitation
Limitations:
Dataset Size: The 1,000-record dataset, while sufficient for proof-of-concept evaluation, is relatively small for production deployment. Larger, more diverse real-world datasets would improve model generalization.
Synthetic Data: The dataset was synthetically generated due to privacy constraints on real institutional data. Performance on genuine lost item records may vary.
YOLO Computational Requirements: YOLOv8 inference requires significant CPU/GPU resources, which may limit deployment on low-specification institutional servers.
Language Support: The current system supports English-language descriptions only. Multi-language support is absent.
No Mobile Application: The system is currently web-only. A dedicated mobile application would improve accessibility and enable camera-based image capture.
SQLite Limitations: SQLite is not suitable for high-concurrency production environments. Migration to PostgreSQL or MySQL would be required for large-scale deployment.
Future Scope:
Multi-Language NLP Support: Integrating multilingual NLP models (e.g., XLM-R) to process item descriptions in Hindi and other regional languages spoken by campus users.
Geolocation-Based Matching: Incorporating GPS data from mobile devices to suggest where lost items might be found based on historical location patterns and campus hotspot analysis.
Push Notifications: Implementing real-time push notifications using Django Channels (WebSockets) to instantly alert item owners when a high-confidence match is identified.
Blockchain-Based Ownership Verification: Exploring blockchain technology for tamper-proof recording of item ownership claims and match histories.
Deep Learning End-to-End Model: Replacing the multi-step feature engineering and ML classifier pipeline with a unified deep learning model (e.g., Transformer-based multi-modal architecture) that jointly processes text and image features.
Mobile Application: Developing native iOS and Android applications using React Native, enabling camera integration for on-the-spot item photography and GPS-based location tagging.
Cloud Deployment: Migrating the system to cloud infrastructure (AWS EC2 + RDS PostgreSQL) for high availability, scalability, and accessibility beyond the campus network.
